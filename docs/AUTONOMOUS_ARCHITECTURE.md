## ۱. ساختار ۴ لایه‌ای سامانه (The 4-Layer Architecture)

سامانه بر اساس تفکیک قطعی مسئولیت‌ها به ۴ لایه مجزا طراحی شده است تا تضمین شود هیچ عامل هوش مصنوعی نتواند قواعد بنیادین مدیریت سرمایه یا راستی‌آزمایی را دور بزند:

```
+-----------------------------------------------------------------------+
|  LAYER D: Experiment & Promotion Manager (مدیریت آزمایش و ترفیع)       |
|  - Champion vs Challenger Engine (مقایسه و ارزیابی استراتژی‌ها)        |
|  - Human Approval Gate (دروازه تایید کاربر برای تغییر نسخه فعال)       |
+-----------------------------------------------------------------------+
                                  ▲
                                  │
+-----------------------------------------------------------------------+
|  LAYER C: AI Research & Improvement (پژوهش، یادگیری و عیب‌یابی)       |
|  - Diagnostics Engine (تفکیک باگ، خطای بروکر و ضرر طبیعی بازار)        |
|  - Trade Autopsy & Mistake Analyzer (تحلیل MAE/MFE و علل ورود/خروج)    |
|  - Hypothesis Registry (دفتر ثبت و آزمون فرضیه‌های کمّی)               |
|  - ML Trade Quality Model (Shadow Mode) (امتیازدهی کیفیت سیگنال)      |
|  - Safe Auto-Fix Pipeline (چرخه ۹ مرحله‌ای با دسته‌بندی ریسک ۳ سطحی)  |
+-----------------------------------------------------------------------+
                                  ▲
                                  │
+-----------------------------------------------------------------------+
|  LAYER B: Continuous Monitoring & Supervision (نظارت مستمر و پایش)    |
|  - Research Supervisor & SQLite Persistent Job Queue                   |
|  - Market Regime Monitor (ATR Ratio, Trend Slope, Fakeout Rate)       |
|  - 6 Scheduled Loops (30s, 15m, 2h, 6h, 24h)                           |
+-----------------------------------------------------------------------+
                                  ▲
                                  │
+-----------------------------------------------------------------------+
|  LAYER A: Real-Time Execution Runtime (موتور اجرای بلادرنگ)           |
|  - Independent Risk Guardian (سقف افت ۲٪، ریسک ۰.۵٪، خنک‌سازی)        |
|  - Internal Paper Broker (ترازنامه دوطرفه Double-Entry Ledger)         |
|  - Next-Bar Open Execution Guarantee (تضمین عدم نشت آینده)             |
|  - Macro News Blackout Engine (بلک‌اوت خبری CPI/NFP/FOMC)             |
+-----------------------------------------------------------------------+
```

## ۲. مشخصات لایه‌ها و تفکیک مسئولیت‌ها

### لایه A: موتور اجرای بلادرنگ (Layer A - Real-Time Runtime)
- **مأموریت:** تضمین پایداری، اجرای بدون نشت آینده و محافظت غیرقابل دستکاری از حساب.
- **اجزا:**
  - `goldlab/paper_broker.py`: مدیریت سفارش‌ها، موقعیت‌ها و دفتر کل تراکنش‌ها (`wallet_ledger`). ترازنامه حساب به صورت تغییرناپذیر ممیزی می‌شود.
  - `goldlab/guardian.py`: ناظر مستقل ریسک که کاملاً خارج از دسترسی مدل‌های زبانی یا عامل‌های خودکار اجرا می‌شود و شروط سخت‌گیرانه (Hard Limits) را اعمال می‌کند.
  - `goldlab/setups.py`: اجرای سیگنال‌ها منحصراً روی قیمت بازگشایی کندل بعد (Next-Bar Open).

### لایه B: پایش مستمر و زمان‌بندی (Layer B - Monitoring & Supervision)
- **مأموریت:** حفظ پیوستگی فعالیت پژوهشی در لپ‌تاپ مکینتاش در بازه چندروزه.
- **اجزا:**
  - `goldlab/supervisor.py`: صف کارهای ناهمگام ذخیره‌شده در دیتابیس SQLite (`supervisor_jobs`) به منظور جلوگیری از دست رفتن وظایف در صورت بسته‌شدن برنامه.
  - `goldlab/regime.py`: ارزیابی بلادرنگ رژیم نوسانی بازار و هشدار در هنگام شرایط متلاطم، اسپرد بالا یا رکود حرکتی.

### لایه C: پژوهش هوشمند و یادگیری (Layer C - AI Research & Improvement)
- **مأموریت:** کالبدشکافی دقیق عملکرد، تولید فرضیه‌های کمّی و پیشنهاد اصلاحات با ریسک کنترل‌شده.
- **اجزا:**
  - `goldlab/diagnostics.py`: تفکیک باگ نرم‌افزاری از ضرر طبیعی بازار و ثبت شناسه خطاهای ساختاریافته.
  - `goldlab/learning.py`: تحلیل MAE/MFE و صدور احکام کالبدشکافی (`GOOD_LOSS`، `CHASED_PRICE`، `TIGHT_STOP`، `ADVERSE_REGIME`، `GOOD_WIN`، `LUCK_WIN`).
  - `goldlab/autofix.py`: ایجاد پیشنهادهای اصلاح با تفکیک ریسک کم، متوسط و بالا همراه با کد آزمون بازتولید (Minimal Reproducer).
  - `goldlab/ml_model.py`: مدل امتیازدهی کیفی در حالت سایه (Shadow Mode) برای برآورد شانس برد $P(\text{Win})$ بدون مسدودسازی معاملات قبل از تایید.

### لایه D: مدیریت آزمایش و ترفیع (Layer D - Experiment & Promotion)
- **مأموریت:** اجرای رقابت بین نسخه قهرمان جاری (Champion) و نسخه‌های رقیب پژوهشی (Challengers).
- **اجزا:**
  - `goldlab/promotion.py`: بررسی شرایط ترفیع (تعداد معامله $\ge 30$، بهبود امید ریاضی $\ge 0.15 R$ و مقدار $p \le 0.05$).
  - **دروازه تایید انسانی:** هیچ نسخه جدیدی بدون تایید صریح کاربر جایگزین Champion نمی‌شود.
