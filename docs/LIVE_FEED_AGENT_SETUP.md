# راهنمای راه‌اندازی قیمت زنده و ناظر Gold Session Lab Pro

## وضعیت پیاده‌سازی (۸ نوامبر ۲۰۲۶)

- فید قیمت: **OANDA v20 read-only PRICE stream**، فقط با حساب معتبر و مجوز دسترسی XAU_USD.
- نرخ دریافت: OANDA حداکثر ۴ قیمت در ثانیه برای هر نماد ارسال می‌کند، نه هر تیک ایجادشده در بروکر.
- Bid/Ask: متن دقیق ارسال‌شده توسط ارائه‌دهنده حفظ می‌شود؛ تعداد اعشار ثابت ۲ رقم نیست.
- نمودار: کندل‌های **کامل‌شده M1 Midpoint** از REST رسمی OANDA، تازه‌سازی دقیقه‌ای؛ خط قیمت لحظه‌ای Mid از Bid/Ask معتبر روی نمودار جداگانه نشان داده می‌شود.
- با قطع اینترنت، قیمت قدیمی، بسته بودن بازار یا نبود مجوز XAU_USD، قیمت زنده و سفارش مجازی جدید متوقف می‌شوند. هرگز قیمت تصادفی یا Demo به جای Live قرار نمی‌گیرد.
- عامل Antigravity: در حال حاضر **External AI runtime متصل نشده است**. AgentBridge شواهد و فایل بررسی می‌سازد و از داخل کد حق سفارش واقعی یا ادغام تغییرات ندارد.
- PAPER_AUTO همچنان بسته است تا ناهماهنگی زمان سیگنال‌ها و نشت آینده در سشن‌ها اصلاح و با دادهٔ واقعی/تست مستقل تأیید شوند.

## تنظیم حساب داده (بدون سفارش واقعی)

از مستندات رسمی OANDA یک حساب دارای REST-v20 و دسترسی به نماد XAU_USD فراهم کنید. دسترسی به XAU_USD بسته به محل اقامت و نوع حساب متفاوت است.

روی مک در پوشه پروژه:

```bash
git fetch origin
git checkout fix/market-data-safety-session-chart
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# مقادیر واقعی را فقط در محیط خصوصی مک قرار بده؛ هرگز در GitHub ذخیره نکن.
export OANDA_ENV=practice
export OANDA_ACCOUNT_ID='YOUR_ACCOUNT_ID'
export OANDA_API_TOKEN='YOUR_READ_ONLY_PRICING_TOKEN'
export GOLDLAB_ENABLE_DEMO_REPLAY=0
python -m pytest -q
python app.py
```

سپس در http://127.0.0.1:8000 بخش XAU/USD و `/api/market/status` را بررسی کن. مقدار `quote_source` باید `OANDA_V20_READ_ONLY` باشد و `quote_time` تازه باشد؛ در زمان تعطیلی بازار `paper_orders_allowed` باید `false` بماند. `OANDA_ENV=live` فقط میزبان **دریافت قیمت** را تغییر می‌دهد و نباید هیچ سفارش واقعی ارسال شود.

> هشدار: مثال بالا می‌گوید `YOUR_READ_ONLY_PRICING_TOKEN`، اما توکن معمول OANDA لزوماً فقط-خواندنی نیست. برنامه فقط endpointهای GET را فراخوانی می‌کند؛ کلید را در GitHub، فایل لاگ یا داشبورد عمومی قرار نده. برای کاهش ریسک از حساب practice اختصاصی استفاده کن.

## بررسی AgentBridge و حافظهٔ تصمیم

- `GET /api/agent/status`: فعالیت ثبت‌شده، نه اثبات اتصال زنده عامل هوشمند.
- `GET /api/agent/advice`: «بار بعد چه کار نکنیم» طبق رویداد واقعی و قوانین ایمنی؛ **یادگیری AI سودآور نیست**.
- `agent-work/REVIEW_TASK.md`: بسته شواهد تولیدشده برای Antigravity، حاوی خطاها، کالبدشکافی معاملات و هشدارهای ایمنی.
- `scripts/agent-observe-loop.sh`: جمع‌آوری دوره‌ای محلی؛ خودِ این اسکریپت هیچ عامل هوش مصنوعی را اجرا نمی‌کند.

اگر Antigravity روی مک قابلیت برنامه‌ریزی/اتوماسیون پشتیبانی‌شده دارد، باید همان Workspace را با فایل `AGENTS.md` و `agent-work/REVIEW_TASK.md` به عامل وصل و خروجی واقعی تست‌ها را در AgentBridge ثبت کرد. اتصال و اجرای خودکار این عامل **جزو موارد تأییدنشده است**. بدون API یا ابزار رسمی متصل‌کننده، نباید آن را با یک وضعیت جعلی «AI connected» نمایش داد.

## دروازه‌های ضروری قبل از Paper Auto

1. منبع داده و ساعات قابل معاملهٔ ارائه‌دهنده، با Bid/Ask قابل ممیزی تأیید شوند.
2. زمان صدور سیگنال، ورود در آغاز کندل بعد، استاپ و ریسک در بازاجرای کندل‌به‌کندل دقیق و بدون سیگنال دیرهنگام باشند.
3. سقف/کف سشن‌ها در هر نقطه از تاریخ فقط از اطلاعات موجود تا همان لحظه محاسبه شوند.
4. آزمایش‌های walk-forward و out-of-sample با اسپرد، اسلیپیج و تعطیلات واقعی انجام شوند.
5. تغییر قوانین استراتژی فقط روی Challenger و بعد از تأیید کاربر به Champion منتقل شود.

هیچ تست نرم‌افزاری به‌تنهایی اثبات سودآوری نیست.
